# audio.cpp Windows cold-read patch

Base: 0xShug0/audio.cpp commit `0bf4d155f2af5f85853415170622dc145e3d62c3`.

This patch preserves the installed native changes outside the ignored local runtime: deferred pinned expert-bank loading in file-offset order, Windows sequential reads directly into pinned buffers, CUDA fixture coverage, and the MSVC test-target exception setting. It does not include models, binaries or local credentials.

Apply once to a clean checkout at the pinned revision, before building:

```powershell
git -C <audio.cpp-checkout> apply --check <absolute-path-to-windows-pinned-sequential-read.patch>
git -C <audio.cpp-checkout> apply <absolute-path-to-windows-pinned-sequential-read.patch>
```

The existing installer does not automatically apply this patch. The checked-in patch was verified with `git apply --reverse --check` against the running local source. The previously built CUDA fixture passed all six modes; live native inference was verified. See `docs/PATCHES.md` for measurements and limitations. No model rebuild was performed for the initial Git delivery.

Upstream-derived code retains the upstream Apache-2.0 license, copied as `LICENSE.upstream`; the root project license does not replace it. The optional C-drive Torch library cache is a machine-local setup, not a repository dependency or committed cache.


Only CPU-written, GPU-read pinned expert banks use the private CUDA host-buffer extension. Ordinary staging/readback, CPU expert paths and tensor arithmetic are unchanged; HIP/MUSA keep their original host buffer type. No public header changes. The installer does not apply this patch automatically. Keep a verified original executable and matching runtime/build receipts before replacing a local runtime; the current machine retains those in `.runtime/writecombined-original`.

All six numeric fixture modes passed with max_abs=0. Three complete full-reference/fixed-seed candidate outputs matched the original512000-byte PCM SHA256 exactly. Warm native first audio measured1.522/1.498s against the current1.574s baseline, but historical timings overlap; no robust overall percentage improvement is claimed. Full synthesis still runs slower than real time, and HDD expert loading still took295.183s. This patch does not solve cold startup or establish fresh user-spoken/listening acceptance. ## Experimental backbone state checkpoint (not enabled)

`experimental-backbone-state-checkpoint.patch` is a separate optional research patch against the same pinned source after the cold-read patch. It adds internal backbone capture/restore methods and a CUDA fixture; no generator, public session API, installer or live configuration calls these methods. It is not a completed reference-prefix cache and does not establish a first-audio speedup.

The checkpoint saves the complete KV capacity, linear-attention convolution tails and recurrent matrices, plus valid step position. Host copies are tied to the exact decoder instance; foreign checkpoints are rejected before writes. Runtime masks/positions are regenerated by the next decode step. Full KV capacity is retained to preserve masked slots and avoid stale/NaN contents. The current standard40-layer/context2048 configuration would require about142.8MiB host memory per backbone checkpoint, calculated from tensor dimensions, not measured with the full model. No additional model or SSD copy is required by the checkpoint itself.

The rebuilt CUDA fixture passed prefix lengths7/129/513/7,16 exact continuation replay comparisons,4 foreign-state rejections and12 injected allocation failures with no tracked buffer leaks. A deliberately KV-only checkpoint failed with `state restore changed continuation output`; restoring the complete implementation passed. The first negative run used a stale fixture executable and is explicitly excluded. The existing NMake directory does not track the fixture's direct inclusion of backbone.cpp; force recompilation of backbone_allocation_test.cpp when changing that included source, or use a freshly configured build with VSLANG=1033 set before configuration. No public header changed in this experiment.

The patch passed forward and reverse checks. After validation both local native source files were restored byte-for-byte; the installed server binary and running native/speech PIDs stayed unchanged. Logs and the fixture executable hash are recorded in `.runtime/prefix-state-checkpoint-result.json` locally. Future activation needs a bounded generator integration, exact cache invalidation for reference/history/settings, split-prefill numerical checks, and full selected-reference PCM/quality/TTFA acceptance. Tower prefill can initially be recomputed from the complete cached-plus-new backbone hidden sequence; it must not be skipped using only a backbone checkpoint.
## Experimental expert-prefix memo (rejected; not enabled)

`experimental-reference-prefix-cache.patch` is retained as an unapplied research artifact after the cold-read patch. Do not combine it with the separate experimental checkpoint patch. It preserves whole-prompt attention/GDN/KV, the original fused finish graph, original expert groups, row positions and transfer order. It caches completed expert/residual rows with bit-identical normalized input, residual and routing keys, bounded to768MiB host arrays plus bookkeeping. Only wholly cached32-row blocks skip computation. This design still failed full-model acceptance.

F32 and Q8_0-backbone/Q4_K-expert CUDA fixtures passed bit-exact prefill/continuation checks at7/129/513/513/129/7-row prefixes, changed input, repeated calls, memory budget and allocation-failure recovery. The standard-config array bound was805235200bytes. These synthetic checks did not establish full-model equivalence. Final full27.9s reference testing returned491520-byte PCM instead of the baseline512000bytes and provided no stable first-audio improvement. Earlier split and reduced-result variants also failed; their0.52–0.80s results are excluded. Preserving the finish graph and transfer schedule was insufficient; the complete numerical root cause remains unresolved.

The original installed server binary and all9 edited native source files were restored and verified against their original SHA256 values. Python does not activate this feature, and production warmup/payload methods retain their previous behavior. This patch is not an optimization delivered to the live application. Future work needs a full-size prefill/decode numerical trace and independently validated output before any activation; do not infer safety from the small fixture.
